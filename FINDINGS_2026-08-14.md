## 1. destiny2.exe is PACKED (VMProtect-style) — static analysis of the file is dead

Evidence (all from our own PE parsing + pattern scans):
- Two `.text` sections (28.9 MB + 81.3 MB) at entropy 8.0 / 7.9 at rest; real code ≈ 6.3–6.7.
- A `.vmp0` section (4.7 MB) — VMProtect's section name; `vmp0` marker in file.
- **Zero of 16 Sunrise byte signatures match the on-disk bytes**, yet Sunrise resolves all 16
  at runtime from the same image ranges (client_hook_activation.cpp → image.cpp uses
  GetModuleHandleW(nullptr)). Sections are decrypted in memory at load.
- Entry point sits in `.text` (not `.vmp0`) — Bungie kept the original entry; custom loader.
- Nobody in the scene had this documented (the bootstrap checklist explicitly asked for a
  packing check — answer: yes, packed).

## 4. The "8 missing patterns" mystery — SOLVED: Detours patches, not encryption

Our dump-scan found 8/16 patterns; the missing 8 are boot-critical hooks. Contradiction
resolved by reading the live process:
- Sunrise hooks 8 of the 16 via Detours (E9 JMP at function entry destroys the prologue
  bytes → pattern scan fails). The other 8 are resolution-only (never patched).
- Hook JMPs land in a Detours trampoline pool at ~0x7FF5F0490000 (96-byte slots:
  `[original prologue bytes][FF 25 rel32][abs ptr][far-stub at +0x58]`). Sunrise's DLL is
  ~318 GB away — Detours used near-stubs (mov rax,imm64; jmp rax).
- Trampoline slots hold the PRISTINE original prologues → pattern-prefix matches recovered
  6 anchors directly (incl. retail_log_enqueue's JZ→0F84 re-encoding).
- Definitive identification: E9 destroys only bytes 0–4; **bytes 5+ are original** → matched
  full patterns against (wildcarded patch + live tail), brute-forcing patch length 5–15
  (must be < pattern length; Detours rounds to instruction boundary, pads with CC).
