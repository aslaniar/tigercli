### ROOT CAUSE (verified end to end in source)

The game's bootflow:content_check compares TWO values inside the client:

1. EXPECTED token: hooks/config_getter/config_getter_answers.cpp
   ensure_token(): when client.external_server.enabled, it returns settings'
   external.configGuid verbatim ("the external server compares this against
   field 5 of the manifest it serves"). The rig carried the MAC-derived
   4979636d-051d-8c5e-b7d1-0f79fdf4abcb.
2. SERVED manifest guid: hooks/network/content_config/request/
   content_config_get_replacement.cpp answers the manifest GET IN-PROCESS
   from state::content_manifest::visit_snapshot - i.e. from the LOCAL
   machine's package scan. Its guid = fingerprint::guid() over
   catalogFingerprint = SHA256(kCatalogDomain + directoryFingerprint +
   rowFingerprint), where directoryFingerprint hashes EACH pkg's stem,
   packageId, patchIndex, file SIZE and lastWriteTime
   (scanner/content_manifest_directory_scan.cpp hash_inventory).

Two copies of the SAME build on different machines therefore produce
DIFFERENT guids (file mtimes differ), while byte-size stays identical (same
rows: both served exactly 105232 bytes, rowCount 2199). The Mac never hits
this because its server packages_dir points at the SAME Game/packages the
Mac client scans - one fingerprint, one guid by construction.
