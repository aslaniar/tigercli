# GAME PLAN — Destiny 1 backend reconstruction (for a CS-background contributor)

Consolidated 2026-08-07 from the verified findings (`FINDINGS_2026-08-07.md`, deep review,
two breadth reviews). Cross-checked by deep (V4 Pro) and horizon (GLM 5.2); a kimi K3 run

## The situation in one paragraph
The D1 client (PS3/X360) is fully obtainable and emulated (RPCS3). The gap is the server:
static config is recoverable TODAY via the still-live Bungie.net API + .pkg files; the
wire protocol is partially reconstructed (V4NGUARD auth/social, kallsyms persistence) but
gameplay messages are unmapped; and the activity state machines are entirely unrecovered.
Live protocol capture is NOT time-limited as of 2026-08-07 — D1's servers are still live with
an active playerbase (user correction; do not claim a shutdown is imminent). Capture remains
valuable but is not urgent.

## Verified anchors (do not re-research)
- D1 on PC = RPCS3 (PS3 build) or XenonRecomp (X360, unproven); content ceiling = The Taken
  King (RoI was PS4/XB1 only).
- Bungie.net API is LIVE (curl 200 on /Platform/Destiny2/Manifest/); D1 Manifest/PGCR return
  307 (alive, need valid API key). [self-verify before relying]

- Off-the-shelf automation: auto-re-agent (AI Ghidra RE agent), DIM (manifest parsing),
  AALpy/PM4Py/gisele (state-machine inference), TrinityCore/AzerothCore (MMO server pattern),
  Aleph One (Bungie's open-sourced Marathon 2 engine — Tiger's ancestor, free vocabulary).

## Strategy: 3 tracks in parallel, all non-urgent
The work does not split by expiry (servers are live, playerbase active). Run Tracks in
parallel by dependency, not by deadline.

**Track A — Static config extraction (no expiry, start today)**
- Verify + pull the D1 manifest via Bungie.net API (needs a free API key); fork DIM's
  manifest loader rather than re-deriving schema.
- Backfill with .pkg data via tiger-pkg; resolve hashes via stanuwu's d2-cui-explorer method.
- Output: structured DB of activities/items/vendors/quests/spawns. Feeds server generator.

**Track B — Client/system discovery (no expiry)**
- Read Aleph One source first — the architectural vocabulary (tags, scenarios, net) Tiger
  inherits. Then Ghidra the D1 PS3 EBOOT, starting at Demonware functions (grep
  `demonware.net` strings), trace back to message dispatch.
- Run auto-re-agent (gta-reversed profile as template) to auto-reconstruct network handlers.
- Output: message schema (JSON) for server→client types. Unblocks Track C. Keep the
  reconstructed client source private (re3/reVC DMCA precedent).

**Track C — Live protocol capture (not urgent, but valuable)**
- Run D1 on console/RPCS3 against live servers; intercept via demonware-companion-style
  hooks + crypto keys found in Track B; record timestamped messages + game state for
  soloable content (strikes/story/patrol cover ~80% of discoverable logic).
- Servers are live (2026-08-07) so there is no shutdown deadline, but capture still unlocks
  what static RE can never recover.

**Track D — Synthesis (after A–C have inputs)**
- Infer activity state machines via AALpy/PM4Py (gisele as reference for unobserved protocols).
- Generate server on the AzerothCore module-per-activity pattern, network layer adapted from
  open-bitdemon-emulator; persistence reuses kallsyms' approach if he open-sources.
- Realistic target: playable strikes/story/patrol with enemies + objectives. Raids, RNG
  loot, anti-cheat, and cut content are out of scope for a first server.
