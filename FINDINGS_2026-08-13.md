## 1. What it actually is: five stacked layers

```
destiny2.exe (Season of Arrivals build, user-supplied via Steam depots)
  └─ steam_api64.dll  ← Sunrise REPLACES this file (DLL proxy/hijack, no injection needed)
      ├─ 1. EGRESS GUARD    air-gap: hooks Winsock + DNS, forces ALL traffic to loopback
      ├─ 2. STEAM SHIM      reimplements SteamAPI_* surface the game expects
      ├─ 3. CLIENT HOOKS    Detours patches: boot flow, spawn gates, UI, teleport, graphics
      ├─ 4. MIDDLEWARE      protocol stack: SignOn, AES-GCM secure channel, protobuf,
      │                     Oodle (borrowed from game's own oo2core_3_win64.dll), .pkg readers
      └─ 5. IN-PROCESS SERVER  TCP listener on 127.0.0.1:30974 speaking "BAP"
                              (Bungie Access Protocol): activity host, matchmaking,
                              push/snapshot queues, inventory/character datagen
```

- **Entry** (`dllmain.cpp`): exports `SteamAPI_Init` etc. plus own `SunriseInitialize` /
  `SunriseActivateClient`. The egress guard installs *first*, before anything else runs.
- **The game client then talks real Bungie protocol to the in-process server.** SignOn
  handshake → server-hello (protobuf: 32-byte session token + protocol version) → encrypted
  AES-GCM frames (16-byte tags, 12-byte LE nonces) → BAP services (activity host manager,
  matchmaking, activity messages, membership, patch epochs) → datagen'd account/characters/
  inventory ("family 3/4" updates) and web-service messages ("family 5", opcodes
  205/501/503/505/601).
- **The protocol families are named in-source**: family 0 ("queuez" = subscription/update
  push queues), family 3 (roster/character publish), family 4 (account/character/instance/
  inventory/loadout/progression), family 5 (investment flags/values via web service).
  [VERIFIED from dir structure + codec files; exact Bungie-side naming is the project's own
  vocabulary.]
- **Oodle legality trick**: Sunrise never ships Oodle. It calls `GetModuleHandleW` on the
  game's own already-loaded `oo2core_3_win64.dll` and compresses/decompresses through it.
  Same pattern as its "no game data shipped" rule — everything copyrighted is borrowed from
  the user's own install at runtime.

## 2. The air-gap is the legal posture, enforced in code

- `client/hooks/egress/`: DNS replacements answer every lookup as `localhost` (cache/local
  only, `DNS_QUERY_NO_WIRE_QUERY`); Winsock connect/send are rewritten to a single loopback
  target or denied with policy logging; reverse-DNS and resolver paths covered.
- PR #10 (SharXeniX, closed unmerged) documents the consequence: under Wine the guard can't
  install, and a latent byte-order bug in the SignOn `relayAddress` field surfaced (client
  dialed `1.0.0.127:30974` instead of `127.0.0.1:30974`). On Windows the guard masked it.
- FAQ: "Can this cause any bans? No. The mod itself does not allow any connections from the
  game to be made." — the air-gap IS the no-ban argument.

## 3. external_server mode — the client half can leave the process [VERIFIED, big deal]

- `client/hooks/external_server/` + settings `client.externalServer.{enabled,host,
  config_url,config_guid}`: rewrites the client's SignOn URLs to an arbitrary host
  (default config_guid literally names it `d2legacy-...`).
- Meaning: **the client-side work (air-gap excepted) already supports pointing the D2 client
  at an external server.** Today the only compatible server is the in-process one, but the
  seam exists. This is the natural future home of a standalone D2 server — and the closest
  open analog to what V4NGUARD keeps closed for D1. [INFERRED as trajectory; the mechanism
  is verified.]

## 6. Install mechanics (for the archive-risk item)

- App **1085660**, depots **1085661** (manifest `7180122903232116872`) and **1085662**
  (manifest `2210332166360342287`) — the Season of Arrivals build, fetched via
  DepotDownloader/steamcmd with an account that owns D2. Then swap
  `bin\x64\steam_api64.dll`, run `destiny2.exe` directly.
- **Existential risk confirmed**: the whole project pins exactly two manifest IDs on Valve's
  CDN. If Valve retires them (or Bungie asks), new users can't obtain the build.
  **Action: archive both depots NOW (≈100GB) while fetchable.** This is the cheapest
  preservation insurance in the entire project.

## 7. Contribution surface (user: CS background, new to game RE) — ranked

   rules (clang-format/clang-tidy enforced).
5. **Medium: quality-of-life features** in his scope (language PR #5 is the template).
6. **Stretch (watch, don't push): enemy/entity work.** The entity_slot transaction plumbing
   is built; PR #9 (persistent inventory) is the test case for whether "exploration only"
   expands. If stan opens that door, static enemy spawns via the spawn-set tables are the
   first tractable step [INFERRED]. Do NOT open a "add enemies" issue — #4 was shot down.
7. **Transferable to D1**: the middleware layer (SignOn, secure channel, BAP service shape,
   protobuf datagen by family) is the only open Tiger-protocol server stack in existence.
   D1's wire format differs (older Demonware), but the *architecture* (air-gapped client +
   in-process server + datagen'd persistence) is the template our D1 Tracks B–D lacked.
